# 中文 Beginner A — Trainer

A small offline app for learning the characters, phrases and vocabulary from the
*中文 Beginner A* textbook (JIC Language School).

## How to open

**Double-click `start.bat`** — it launches a tiny local server and opens the app
in your browser. Keep the little black window open while you study; close it when
you're done. (Running via the server makes audio and stroke/writing practice work
reliably in every browser.)

You can also just double-click `index.html` to open it directly — everything
works offline except that some browsers mute the audio on `file://` pages.

## On your iPhone / iPad (private — nothing published)

1. On the PC, double-click **`start.bat`** and keep the window open. It prints the
   address to use on your phone (e.g. `http://192.168.1.103:8000/index.html`).
   The first time, Windows may ask to allow Python through the firewall — click **Allow**.
2. On the iPhone/iPad (**same Wi-Fi**), open that address in **Safari**.
3. Tap **Share → Add to Home Screen** to get the 中 app icon; it opens full-screen
   like a normal app.

Notes:
- This stays on your home network — it's never put on the public internet.
- The PC must be on and on the same Wi-Fi (this is a LAN connection, not offline).
- The 🎤 speaking-check doesn't appear on iOS (Safari has no speech recognition);
  everything else — writing, flashcards, quizzes, 🔊 audio, roleplay — works.
- **Fully offline on the device** (PC off) needs the app served over HTTPS —
  browsers only enable the offline cache on a secure origin. See
  *Deploying* below; once it's on GitHub Pages and added to your Home Screen,
  it works with no signal and no PC.

## What it does

- **Study (spaced repetition)** — flashcards that resurface the words you find
  hard and space out the ones you know. Your progress is saved in the browser.
  Grade each card *Again / Good / Easy* (keys **1 / 2 / 3**; **Space** reveals).
- **Quiz** — multiple-choice test across whichever focuses you enable.
- **Browse list** — every word in a table, each with an audio button.

- **Converse (speaking)** — roleplay a short dialogue from the lessons: the app
  speaks a line, then it's your turn. Say your reply out loud and it checks your
  pronunciation (🎤), or tap "I said it" to move on. Each line has 🔊 normal and
  🐢 slow playback. Speaking-check uses your browser's speech recognition
  (**Chrome/Edge**, needs mic permission + internet); everything else works
  without a mic.
- **Say it & check** — on the pronunciation flashcard, a 🎤 button lets you speak
  the word and get instant feedback on whether it matched.

Five practice directions you can toggle on the home screen:
recognise characters, recall from English, pronunciation/pinyin, listening
(spoken via your browser's Chinese text-to-speech voice), and **write it** —
draw the character from memory and it checks each stroke.

- **Stroke order & writing** — tap the **✍︎** button on any word (in Browse or on
  a revealed flashcard) to watch each character drawn stroke by stroke, or to
  practise writing it yourself with stroke-by-stroke checking and hints.
- **Writing sheet (字帖)** — from that character view, tap **📝 Writing sheet** for a
  repetitive tracing copybook: a header card (pinyin, meaning, stroke count,
  example words) and a grid of 田字格 boxes that fade from traceable outline to
  blank. Trace them on screen, or hit **🖨 Print sheet** to print a proper paper
  copybook and practise with a pen.

Stroke data lives locally in `hanzi-data.js`, generated by `fetch-hanzi-data.js`
(run `node fetch-hanzi-data.js` once after adding new lessons to download any new
characters). The writing engine is Hanzi Writer, vendored in `vendor/`.

## Adding lessons safely

After editing `data.js`, run:

```
node validate-data.js      # check it
node fetch-hanzi-data.js   # download stroke data for any new characters
```

The validator catches the mistakes that fail **silently** in the app rather than
throwing an error:

| Problem | Why it matters |
|---|---|
| Pinyin doesn't line up with the characters | The line is **dropped entirely** — no sentence-building tiles and no speaking phrase — with no error shown |
| Missing stroke data for a character | Writing practice can't run for that word |
| Duplicate word | Hidden (first lesson wins), so it looks like it "didn't get added" |
| Duplicate lesson id, missing hanzi/pinyin/en | Breaks the lesson outright |
| Missing tone marks, odd characters | Usually a transcription slip |

⚠️ **Keep the order of existing words stable.** Card IDs are `lessonId:index`, so
inserting or removing a word in the middle shifts every ID after it — which
silently reassigns saved progress (and cloud-synced progress) to the wrong words.
Append new words to the end of a lesson, and add new lessons as new entries.

## The vocabulary

All words live in **`data.js`**, transcribed by hand from the textbook scans so
the tone marks are correct. To add a lesson, append another object to
`VOCAB.lessons` following the same shape. Keep the order of existing words stable
(progress is keyed by position).

Loaded: **Useful Expressions**, **Lessons 1–6**, plus themed sets
(**Countries/People/Languages** and **Numbers 0–1000**) — 158 unique words in all,
covering the whole Beginner A book.

A word that the book re-teaches in a later lesson is shown once, in the lesson
where it first appears, so you never get duplicate flashcards.

## Accounts & sync

Progress lives in `localStorage`, which iOS can evict if the app sits unused —
so the app also syncs to [Supabase](https://supabase.com) when signed in.

It is **local-first**: localStorage stays the source of truth, everything works
offline, and signing in only adds a cloud copy. Sync **merges** rather than
overwrites — lessons are unioned, daily activity takes the max per day, and the
more-reviewed SRS entry wins — so using two devices can't cost you progress.

Config sits at the top of the `ACCOUNT + CLOUD SYNC` section in `app.js`:

```js
const SUPABASE_URL = "https://<project>.supabase.co";
const SUPABASE_ANON_KEY = "<anon public key>";
```

⚠️ That **anon key is public by design** — it is meant to be embedded in a client
and is safe in a public repo. What actually protects the data is **row-level
security** in Postgres:

```sql
create table if not exists public.progress (
  user_id uuid primary key references auth.users(id) on delete cascade,
  data jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);
alter table public.progress enable row level security;
create policy "own progress" on public.progress
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

**Never** put the Supabase `service_role` key in this file — it bypasses the
policy above entirely and would expose every user's data.

## Deploying (GitHub Pages)

All paths are relative, so it works served from a subfolder with no changes.

1. Create an empty repo on GitHub
2. `git remote add origin <url>` then `git push -u origin main`
3. Repo → Settings → Pages → deploy from `main`, folder `/ (root)`
4. Open the `https://<user>.github.io/<repo>/` URL on your phone in Safari →
   Share → **Add to Home Screen**

Bump `CACHE` in `sw.js` and the `?v=` query on assets whenever you change app
files, or devices will keep serving the cached copy.
